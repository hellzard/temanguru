# Product Slicing

1. Read `docs/PRD.md`, `docs/ROADMAP.md`, and `docs/TASKS.md`.
2. State the user problem and what repeated work is removed.
3. Define one end-to-end slice with a visible user outcome.
4. Include happy path, offline/error states, authorization, and export implications.
5. Write measurable acceptance criteria without invented business metrics.
6. Mark anything not needed for this slice as out of scope.

A slice is too large when it needs more than one primary data model, more than two new routes, or cannot be verified in one E2E flow.
